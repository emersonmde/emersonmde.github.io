# Error Signal — retired

This site has moved to **[memerson.com](https://memerson.com)**.

`errorsignal.dev` now serves nothing but redirects. Every old URL — `/`, `/about`, `/blog`,
`/blog/<slug>`, `/photos` — is a page whose only job is to forward to its equivalent on the
new site. The TUI implementation this repo used to hold was removed when the redirects
landed; it is still in the git history.

The new site lives in a separate repo and is a completely new design. Only the _content_
(blog posts, projects, about copy) carried over, with every blog slug preserved, so the old
URLs map 1:1.

## Why the redirects live here and not on the domain

`errorsignal.dev` is shared. Several other repos publish to it through GitHub Pages —
`coppermind`, Rust docs, other static assets — and they keep working from it. Putting the
redirects in this repo means those are untouched by construction, with no domain-level rule
a future project could accidentally match.

## Why they are meta refreshes

GitHub Pages cannot emit a 301. An instant (0-second) `<meta http-equiv="refresh">` is the
strongest mechanism available, and
[Google interprets it as a permanent redirect](https://developers.google.com/search/docs/crawling-indexing/301-redirects).
Each page also sets `rel="canonical"` to the new URL.

These are hand-written rather than generated by Astro's `redirects:` config, which emits
the same meta refresh but adds `<meta name="robots" content="noindex">` — that would block
the old URL from Search instead of passing its signals to the new one. See
`src/layouts/Moved.astro`.

`/rss.xml` is the exception: GitHub Pages serves `.xml` as XML, so a meta refresh there
would arrive as a parse error. It stays a valid feed containing a single item pointing at
the new one.
